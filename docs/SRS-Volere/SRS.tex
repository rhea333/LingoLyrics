\section{Purpose of the Project}
\subsection{User Business}
Language learners who study on their own at early intermediate to intermediate levels
often use songs to hear vocabulary, idioms, and cultural references as native
speakers use them. Media players and lyrics websites do not support studying
this material. When a learner meets an unfamiliar word, they have to pause the
audio, look the word up in another tool, and copy it into a flashcard
application by hand. This interrupts listening and separates the word from the
lyric that gives it its meaning.

\progname{} combines synchronized lyrics, translations of each line,
transliterations for scripts other than Latin, contextual annotations, and vocabulary
export to Anki in one workflow.

\subsection{Goals of the Project}
The goals below are taken from the Problem Statement and Goals document. Each
goal's measure is refined into the requirements listed in
Table~\ref{TblGoalTrace}.

\begin{itemize}
    \item[G1] \textbf{Synchronized Lesson Playback:} highlight each lyric line
    within \cn{SYNC\_TOL} of its mapped timestamp for at least \cn{SYNC\_PASS}
    of line transitions in the acceptance suite.
    \item[G2] \textbf{Vocabulary Support in Context:} show the translation and
    contextual annotation of every annotated target when it is selected.
    \item[G3] \textbf{Interoperability between Creators and Learners:} a song map created by
    the editor validates against one shared format and opens in the learner app
    without manual changes.
    \item[G4] \textbf{Practical Lesson Creation:} at least \cn{CREATE\_PASS} test
    creators produce a complete map for a test track of at most
    \cn{TEST\_TRACK\_LINES} lines within \cn{CREATE\_TIME}, without editing
    the map file by hand.
    \item[G5] \textbf{Support for Different Writing Systems:} display lyrics correctly for
    \cn{LANG\_COUNT} languages, at least one with a writing system other than Latin,
    with word divisions and transliterations that match the song map.
    \item[G6] \textbf{Vocabulary Retention Handoff:} sending a selected item
    creates an Anki note with correct \emph{Term}, \emph{Translation}, and
    \emph{Context} fields.
\end{itemize}

\subsection{Hands-On Users of the Project}
\begin{itemize}
    \item \textbf{Learners:} use the mobile app on an iOS or Android phone,
          usually with headphones, to study song lessons. They are assumed to
          be comfortable with common phone apps and to have at least
          beginner knowledge of the target language. They are not assumed to
          know linguistic terms such as \emph{segmentation}.
    \item \textbf{Creators:} language tutors or advanced learners who use the
          web editor on a laptop or desktop computer to time lyrics and write
          translations and annotations. They are assumed to read the target
          language well and to be able to work with audio and text files.
\end{itemize}

\section{Mandated Constraints}
\subsection{Solution Constraints}
\begin{itemize}
    \item[MC1] All application code and the shared song map types shall be
    written in TypeScript.
    \\\textit{Rationale:} one language for the app, editor, and shared code
    lets all three use the same song map types and validator.
    \item[MC2] The learner app shall be built with React Native and Expo. The
    editor shall be built with React.
    \\\textit{Rationale:} one code base covers iOS and Android, and the editor
    can reuse the app's TypeScript code (Development Plan, Expected
    Technology).
    \item[MC3] Lessons shall be stored and exchanged as song maps that conform
    to one versioned JSON Schema.
    \\\textit{Rationale:} required by goal G3.
\end{itemize}

\section{Relevant Facts And Assumptions}
\subsection{Relevant Facts}
\begin{itemize}
    \item Japanese is written without spaces between words and mixes kanji,
          hiragana, and katakana. Many kanji have more than one reading, and
          the correct reading depends on the context.
    \item Anki stores notes in decks. Each note has a note type that defines
          its fields.
    \item AnkiConnect runs only with desktop Anki. AnkiDroid provides an API
          that other Android apps can use to add notes once the user grants
          permission.
    \item Mobile operating systems control audio routing, system volume, and
          when background apps are suspended.
\end{itemize}

\subsection{Business Rules}
\begin{itemize}
    \item \textbf{BR1 (Open Access):} no user account or payment is required to
          open a song map.
    \item \textbf{BR2 (Schema Adherence):} a song map must pass validation
          (Section~\ref{SecFormal}) before the editor exports it or the learner
          app opens it.
    \item \textbf{BR3 (Copyright Compliance):} the project does not distribute
          audio or lyrics unless they are created by the team, in the public domain,
          or licensed for that use.
\end{itemize}

\subsection{Assumptions}
\begin{itemize}
    \item[A1] Learners have an iOS or Android phone that meets the minimum
    operating system version of the Expo SDK release used.
    \\\textit{Rationale:} the app cannot run on older systems. This is a
    platform limit, not a design choice.
    \item[A2] Creators have the audio and lyric text for the songs they map,
    and the right to use them.
    \\\textit{Rationale:} the editor does not supply content (BR3, LG1).
    \item[A3] Learners who want to export vocabulary have Anki installed on
    the device that receives the notes.
    \\\textit{Rationale:} \progname{} is not a flashcard application. It hands
    vocabulary to Anki (G6).
    \item[A4] Software from other vendors (the operating systems, browsers, Anki,
    AnkiDroid, and AnkiConnect) behaves as described in its documentation.
    \\\textit{Rationale:} defects inside that software are outside the
    team's control. The app must still detect and report a failed handoff
    (IN8).
\end{itemize}

Song maps and their creators are not assumed to be free of errors or trustworthy.
Requirements IN2, IN4, IN5, IM1, and IM2 handle incorrect or malicious song
maps.

\section{The Scope of the Work}
\subsection{The Current Situation}
To study a song today, a learner plays it in a music app, reads the lyrics and
a translation on a separate website, looks up words in a dictionary, and types
useful words into Anki. Creators who want to share a song lesson have no
common format, so each lesson is prepared by hand in documents or slides, and
timing is not recorded.

          it while the current line is highlighted, selects words to read
          their meaning, and sends useful words to Anki (events E2 to E5).
\end{itemize}

\section{Business Data Model and Data Dictionary} \label{SecDataModel}
\subsection{Business Data Model}
A \textbf{song map} contains:
\begin{itemize}
    \item \textbf{Metadata:} schema version, title, artist, target language,
          difficulty level, explicit content flag, audio file path, audio
          duration, audio and lyric source and licence, and export history.
    \item \textbf{Lyric lines:} start time, end time, original text, line
          translation, and an ordered list of words.
    \item \textbf{Words:} surface text, reading or transliteration,
          optional start and end time, translation, and a verified flag.
    \item \textbf{Annotations:} the word or line range they apply to, a
          contextual explanation, an optional note on register (how formal or offensive a term is), the author,
          and the review status.
\end{itemize}

\section{The Scope of the Product}
\subsection{Product Boundary}
The product consists of the learner app, the editor, and the shared core.
Anki, AnkiDroid, AnkiConnect, the phone and computer operating systems, and
the source of the audio and lyric content are outside the boundary. The
initial release has no user accounts, no server, and no cloud storage. Song map
packages are moved between the editor and the learner app as files.

\subsection{Individual Product Use Cases (PUC's)}
\begin{itemize}
    \item \textbf{PUC1 (Play synchronized lesson):} the learner opens a
          song map package. The app validates it and shows the lesson. The
          learner presses play. The app plays the audio and highlights the
          current line and word. If validation fails, the app shows the
          reason and does not open the lesson.
    \item \textbf{PUC2 (Inspect a word or line):} the learner taps a word or
          line. The app shows the translation, reading, and annotation, if
          any, without stopping playback.
    \item \textbf{PUC3 (Send a term to Anki):} the learner taps \emph{Add to
          Anki} on a selected word. The app builds a
          \texttt{VocabularyPayload}, sends it to Anki, and shows whether the
          note was created. If sending fails, the item is kept in a queue.
    \item \textbf{PUC4 (Author a song map):} the creator loads audio and
          lyric text, marks line start times while the audio plays, adjusts
          times, reviews the suggested segmentation and readings, enters
          translations and annotations, previews the lesson, and exports it.
          Export is refused until the map is valid.
\end{itemize}

\section{Functional Requirements}
\subsection{Functional Requirements}

\subsubsection*{Learner app}
\begin{description}
\item[FR1] The learner app shall let the learner open a song map package from
the device's storage and shall validate it (Section~\ref{SecFormal}) before
showing the lesson.
\rat{Learners receive lessons as files in the initial release. Only valid maps
can be played correctly.}
\fit{Every map in the acceptance suite opens. Every map in a set of invalid
test maps is rejected with a message naming the failed rule.}
\trace{G3, PUC1, IN2, IN3, IN11.}

\item[FR2] The learner app shall list the lessons it has opened, showing each
lesson's title, artist, language, difficulty, and explicit content flag.
\rat{Learners choose lessons by song and by level.}
\fit{All listed fields match the song map metadata for every acceptance suite
map.}
\trace{G3, PUC1, HS6, HS7.}

\item[FR3] The learner app shall provide play, pause, and seek controls, and
a control that restarts the current line.
\rat{Learners replay short sections to catch words.}
\fit{After each control is used, the reported audio position equals the
expected position within \cn{SYNC\_TOL}.}
\trace{G1, PUC1, HS1.}

\item[FR4] During playback, the learner app shall highlight the line that is
active at the current audio position, as defined by \textit{active} in
Section~\ref{SecFormal}.
\rat{This is the main function of the lesson player.}
\fit{In the acceptance suite, at least \cn{SYNC\_PASS} of line transitions
occur within \cn{SYNC\_TOL} of their mapped start times.}
\trace{G1, PUC1, IN1, PA1.}

\item[FR5] When the active line has word timings, the learner app shall also
highlight the active word.
\rat{Word timing helps learners match syllables to sounds, especially in fast
songs.}
\fit{As FR4, applied to word start times.}
\trace{G1, PUC1.}

\item[FR6] The learner app shall display each line in its original script with
the stored segmentation, and shall let the learner show or hide the
transliteration and the line translation.
\rat{Learners at different levels need different amounts of support.}
\fit{For every line in the acceptance suite, the displayed words and readings
match the song map, and each layer can be turned on and off.}
\trace{G5, PUC2, IN4, IN12.}

\item[FR7] When the learner selects a word or line, the learner app shall
display its translation, reading, and contextual annotation, if present,
without stopping playback.
\rat{Meaning is clearer when shown next to the lyric (G2).}
\fit{Every annotated target in the acceptance suite shows its translation and
annotation when selected.}
\trace{G2, PUC2, SL2.}

\item[FR8] When the learner sends a selected word to Anki, the learner app
shall create a note in the \progname{} deck whose \emph{Term},
\emph{Translation}, and \emph{Context} fields contain the word, its
translation, and the line it appears in.
\rat{Connects song study to spaced repetition review (G6).}
\fit{For each acceptance suite language, a sent word appears in the test deck
with all three fields correct.}
\trace{G6, PUC3, IN8, IN9, IN10, AC1.}
\end{description}

\subsubsection*{Editor}
\begin{description}
\item[FR9] The editor shall let the creator load an audio file and lyric text,
and open an existing song map for editing.
\rat{Creators start from material they already have, and correct maps later.}
\fit{The test track's audio and lyrics load, and a previously exported map
reopens with no data lost.}
\trace{G4, PUC4.}

\item[FR10] The editor shall let the creator mark the start time of each line
while the audio plays, and adjust start and end times by hand.
\rat{Marking times while listening is faster than typing them (G4).}
\fit{Measured by G4 in usability testing.}
\trace{G1, G4, PUC4, IN7.}

\item[FR11] For a supported language without spaces between words, the editor
shall suggest a segmentation and readings for each line and let the creator
accept or correct them.
\rat{Automatic suggestions reduce work. Creator review corrects errors in lyric

\section{Formal Specification} \label{SecFormal}

This section defines a valid song map, the line that is active at a given
audio position, and the learner app's playback modes. Constants are listed in
Appendix~\ref{SecConstants}.

\subsection{Song Map}
A song map is a tuple $S = (v, d, L, N)$ where $v = (v_{\mathit{maj}},
v_{\mathit{min}}, v_{\mathit{pat}})$ is the schema version, $d \in
\mathbb{R}^{+}$ is the audio duration in seconds, $L = \langle \ell_1, \ldots,
\ell_n \rangle$ is the sequence of lines, and $N$ is the set of annotations.
Each line is $\ell_i = (s_i, e_i, W_i)$ with start time $s_i$, end time $e_i$,
and words $W_i = \langle w_{i,1}, \ldots, w_{i,m_i} \rangle$. A word
$w_{i,j}$ has a verified flag $\mathit{ver}_{i,j}$ and optional times
$s_{i,j}, e_{i,j}$. An annotation $a \in N$ has a translation
$a.\mathit{tr}$ and a note $a.\mathit{note}$.

$S$ is valid, written $\mathit{valid}(S)$, when all of conditions V1 to V8
hold:
\begin{description}
\item[V1] (version) $v_{\mathit{maj}} \in \cn{SUPPORTED\_MAJOR}$ (IN3).
\item[V2] (at least one line) $n \ge 1$.
\item[V3] (lines inside the audio) $\forall i \in [1..n] : 0 \le s_i < e_i
\le d$.
\item[V4] (lines ordered, no overlap) $\forall i \in [1..n-1] : e_i \le
s_{i+1}$.
\item[V5] (words inside their line) for every word $w_{i,j}$ that has times,
$s_i \le s_{i,j} < e_{i,j} \le e_i$.
\item[V6] (segmentation verified) $\forall i, j : \mathit{ver}_{i,j}$ (IN4).
\item[V7] (annotations complete) $\forall a \in N : a.\mathit{tr} \neq
\varepsilon \wedge a.\mathit{note} \neq \varepsilon$.
\item[V8] (audio reference and limits) the audio path is relative (IM2),
$|d - d_{\mathit{audio}}| \le \cn{AUDIO\_DUR\_TOL}$ (IN11), the map size is
at most \cn{MAX\_MAP\_SIZE}, and its nesting depth is at most
\cn{MAX\_NESTING} (IM1).
\end{description}
Here $d_{\mathit{audio}}$ is the duration of the decoded audio file and
$\varepsilon$ is the empty string. The JSON Schema checks structure and types.
The shared validator checks the remaining conditions (FR16).

\subsection{Active Line and Synchronization}
For an audio position $p$, the active line is
\[
\mathit{active}(p) =
\begin{cases}
i & \text{if } s_i \le p < e_i\\
\bot & \text{if no line satisfies } s_i \le p < e_i
\end{cases}
\]
which is well defined because valid lines do not overlap. Let $h_i$ be the
audio position at which the learner app changes the highlight to line $i$.
A transition is on time when $|h_i - s_i| \le \cn{SYNC\_TOL}$. FR4 requires
that, over all transitions in the acceptance suite,
\[
\frac{|\{ i : |h_i - s_i| \le \cn{SYNC\_TOL} \}|}{\text{number of transitions}}
\ \ge\ \cn{SYNC\_PASS}.
\]

\subsection{Playback Modes}
The learner app is in one of the modes \textit{NoLesson}, \textit{Ready},
\textit{Playing}, and \textit{Paused}. The initial mode is \textit{NoLesson}.
Table~\ref{TblModes} gives the transitions. Events not listed for a mode leave
the mode unchanged. In \textit{Playing} and \textit{Paused}, the highlighted
line is $\mathit{active}(p)$, where $p$ is the position reported by the audio
player.

\begin{table}[h!]
\caption{Learner app playback mode transitions} \label{TblModes}
\begin{tabularx}{\textwidth}{P{0.15\textwidth}P{0.30\textwidth}XP{0.13\textwidth}}
\toprule
\textbf{Mode} & \textbf{Event} & \textbf{Action} & \textbf{New mode}\\
\midrule
NoLesson & open $S$, $\mathit{valid}(S)$ & $p := 0$ & Ready\\
NoLesson & open $S$, $\neg\mathit{valid}(S)$ & show failed rules & NoLesson\\
Ready & learner presses play & start audio, fade in & Playing\\
Playing & learner presses pause & stop audio & Paused\\
Playing & audio output disconnected & stop audio within
\cn{DISCONNECT\_PAUSE} & Paused\\
Playing & end of audio & $p := d$ & Paused\\
Playing, Paused & seek to $t$ & $p := t$. Highlight $\mathit{active}(t)$ &
unchanged\\
Paused & learner presses play & start audio, fade in & Playing\\
any & close lesson & stop audio & NoLesson\\
\bottomrule
\end{tabularx}
\end{table}

No transition enters \textit{Playing} except a learner action, which is HS1.
The transition on audio output disconnection is HS2.

the date and the creator who exported it.
\rat{Allows changes to a lesson to be traced.}
\fit{Exporting a map twice adds two entries to \texttt{exports}.}
\trace{Hazards H3.1, H5.2.}
\end{description}

\subsection{Immunity Requirements}
\begin{description}
\item[IM1] The song map parser in both the editor and the learner app shall
reject a map whose size exceeds \cn{MAX\_MAP\_SIZE} or whose nesting depth
exceeds \cn{MAX\_NESTING} before parsing it fully, and both shall display all
map text as plain text, never as HTML.
\rat{Prevents denial of service and script injection through crafted maps.}
\fit{Oversized, deeply nested, and test maps containing script are rejected or
shown as plain text.}
\trace{Hazard H4.3.}

\item[IM2] Song maps shall refer to audio and other resources only by relative
paths inside the map package. The validator shall reject absolute and remote
URLs.
\rat{Prevents the app from contacting unknown servers.}
\fit{Maps with absolute paths or URLs are rejected.}
\trace{Hazards H4.4, H7.2.}
\end{description}

\section{Cultural Requirements}
\subsection{Cultural Requirements}
\begin{description}
\item[CU1] Japanese romanization shall follow modified Hepburn
romanization.
\rat{A single standard makes readings consistent across lessons. Hepburn is
the system most used in learning material written in English.}
\fit{Romanization of the Japanese acceptance suite map matches Hepburn for every
word.}
\trace{G5, FR6.}

\item[CU2] Contextual annotations for culturally specific references (for
example, place names, holidays, or idioms) shall explain the reference rather
than only translate it.
\rat{A literal translation can hide the meaning.}
\fit{Review of the acceptance suite annotations.}
\trace{G2, IN5.}
\end{description}

The explicit content requirement HS6 also addresses cultural sensitivity.

\section{Compliance Requirements}
\subsection{Legal Requirements}
\begin{description}
\item[LG1] The editor shall require source and licence information for the
audio and lyrics before a map can be exported, and the learner app shall show
these credits for each lesson.
\rat{Distributing unlicensed lyrics or recordings creates legal liability
(BR3).}
\fit{Export is refused when licence fields are empty. Credits appear in each
acceptance suite lesson.}
\trace{Hazard H5.4.}
\end{description}

Because the product collects no personal data (PR1), no privacy legislation
applies to the initial release beyond what the operating systems require for
permission prompts (PR2).

\subsection{Standards Compliance Requirements}
\begin{description}
\item[ST1] The learner app's text and highlight colours shall meet WCAG 2.1
level AA contrast (Success Criterion 1.4.3), and highlighting shall meet
Success Criterion 2.3.1 (HS4).
\rat{WCAG is the common accessibility standard for web and mobile interfaces.}
\fit{Contrast checker on every text and highlight colour pair.}
\trace{HS4, HS5.}

\item[ST2] The song map schema shall be written in JSON Schema (the December 2020 draft) and song maps shall be valid JSON (RFC 8259) encoded in UTF-8.
\rat{Standard formats allow existing validators and editors to be used.}
\fit{The schema validates against the metaschema of that draft.}
\trace{G3, MC3.}
\end{description}

\section{Open Issues}
\begin{itemize}
    \item \textbf{Anki handoff method.} Whether the learner app uses the
          AnkiDroid API, AnkiConnect, an export file, or a combination
          depends on the PoC (risk R3). On iOS no direct method has been
          confirmed. Affects OE2, AC2, PR2, IN8 to IN10.
    \item \textbf{Mobile timing accuracy.} Whether Expo Audio reports position
          accurately enough for FR4 depends on the PoC (risk R1).
    \item \textbf{Second language.} Japanese is the language whose writing system is not Latin. The
          second language for G5 has not been chosen.
    \item \textbf{Japanese tokenizer.} kuromoji.js is the current choice for
          FR11. Sudachi is more accurate but needs a separate service. Because
          segmentation runs in the editor (IN4), either is possible.
    \item \textbf{Lesson distribution.} The initial release moves song map
          packages as files. Whether lessons should also be bundled with the
          app for the demonstration is undecided.
    \item \textbf{Loudness normalization.} The Hazard Analysis (H1.2) recommends
          that the editor report track loudness. The method and target level
          are not yet defined.
\end{itemize}

\section{Off-the-Shelf Solutions}
\subsection{Ready-Made Products}
\begin{itemize}
    \item \textbf{LyricsTraining:} a web and mobile game in which learners fill
          in missing words in song lyrics. It does not provide annotations,
          transliteration, or Anki export.
    \item \textbf{Musixmatch:} shows lyrics synchronized with the audio and, for some songs,
          translations. It is not designed for study and does not export
          vocabulary.
    \item \textbf{Language Reactor:} a browser extension that shows dual
          subtitles and saves words on video sites. It depends on existing
          subtitles and does not support annotations written by creators for
          songs.
\end{itemize}
None of these combines annotations written by creators, verified segmentation for scripts other than Latin, and Anki export, which are goals G2, G5, and G6.

\subsection{Reusable Components}
\begin{itemize}
    \item kuromoji.js for Japanese segmentation and readings (FR11).
    \item A JSON Schema validator library for FR16.
    \item Expo Audio and Howler.js for playback (FR3, FR13).
    \item Anki, AnkiDroid, and AnkiConnect as the flashcard system (FR8).

The LRC lyric file format stores lines as \texttt{[mm:ss.xx] text}, and its

same model, and the editor may import LRC files in a later release
(stretch goal: song map import and export).

\section{New Problems}
\subsection{Effects on the Current Environment}
Learners will move some song study from several separate tools into one app.
Creators will need to record licence information they may not have recorded
before (LG1).

\subsection{Effects on the Installed Systems}
The learner app adds notes to the learner's Anki collection and may create a
\progname{} deck and note type (AC1). If AnkiConnect is used, the learner must
change its configuration (AC2).

\subsection{Potential User Problems}
\begin{itemize}
    \item Learners may import songs they do not have the right to use. The
          product cannot prevent this for personal files (BR3 applies only to
          content the project distributes).
    \item Learners may rely on transliteration and not learn to read the
          original script. UH3 lets them hide it.
    \item Learners may use the app while moving (HS3).
\end{itemize}

\subsection{Limitations in the Anticipated Implementation Environment That May
Inhibit the New Product}
\begin{itemize}
    \item The interval at which Expo Audio reports playback position limits
          highlight accuracy (risk R1).
    \item iOS does not provide a confirmed way for another app to add notes to
          Anki directly (OE2).
    \item Mobile operating systems may suspend apps in the background, which
          affects highlight alignment after return (IN1).
\end{itemize}

\subsection{Follow-Up Problems}
Changes to the song map schema after lessons are published will require older
maps to remain readable (LO1) or a conversion tool (stretch goal).

\section{Migration to the New Product}
\subsection{Requirements for Migration to the New Product}
\progname{} is a new product and does not replace a deployed application, so
no user accounts, lesson libraries, or other data need to be migrated for the
initial release.

Creators produce new song maps with the editor, and learners open song maps
that conform to the shared, versioned JSON Schema. Later versions may add
import or conversion tools if an earlier schema version or an external lesson
format must be supported.

\subsection{Data That Has to be Modified or Translated for the New System}
No existing data must be converted for the initial release. Each lesson is
authored directly in the song map format and validated before use.

If the schema's major version changes in a later release, a reader for the old
version or a documented conversion process will be required so that existing
valid maps remain usable (LO1). Translation, transliteration, timing, and
annotation data are stored as explicit song map fields and do not need
conversion in the initial release.

\section{Ideas for Solution}
The proposed solution consists of a mobile learner app, a song map editor that runs in a web browser, and a shared TypeScript core. The learner app plays lesson audio,
displays synchronized lyric lines, shows translations, transliterations, and
annotations, and sends selected vocabulary to Anki. The editor creates and
validates song maps without requiring creators to edit JSON files.

A versioned JSON Schema defines the song map, including metadata, timed lyric
lines, words, translations, transliterations, and annotations. Using one
validated format lets lessons created in the editor open in the learner app
without changes.

The current implementation direction is React Native with Expo for the learner
app, React for the editor, and TypeScript for the shared schema and validation
logic. Japanese segmentation and romanization may use kuromoji.js in the
editor. These are implementation ideas, not requirements. Other technologies
may be used if the requirements and constraints are met.
